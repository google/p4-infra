# Entity and RPC Translation

## Overview

This page covers how PDPI translates P4Runtime entities and RPC messages between
the `PD`, `IR`, and `PI` representations. Every `PD <-> PI` conversion goes
through `IR`, so PDPI never generates per-program C++ translator code. `IR`
translation enforces the P4Runtime specification rules once, against `IrP4Info`,
and [`pd.cc`](../pd.cc) handles any generated PD proto by reflection, relying on
a fixed field-naming contract shared with [`pdgenlib.cc`](../pdgenlib.cc)
([pd_codegen_and_p4info_union.md](pd_codegen_and_p4info_union.md)).

    *   [`translation_options.h`](../translation_options.h):

*   **`PD` reflection boundary**:

### Key APIs

*   `CreateIrP4Info`: Takes a compiled `p4.config.v1.P4Info` and returns a
    validated `IrP4Info` with resolved format annotations, reference graphs, and
    table dependency ranks.
    *   Fails with `InvalidArgumentError` on duplicate IDs or aliases, invalid
        `@format` or `@proto_id` annotations, `RANGE` match fields, or cyclic
        table references.
    *   Fails with `NotFoundError` when a reference or cross-reference names an
        unknown table, match field, action, or action profile.
    *   Fails with `UnimplementedError` on unsupported `@refers_to` /
        `@referenced_by` shapes, or when a table's action profile disagrees with
        `@oneshot`.
*   `PiEntityToIr` / `IrEntityToPi`, plus batch, packet, and RPC counterparts
    such as [`PiWriteRequestToIr`](../ir.h), [`IrWriteRequestToPi`](../ir.h),
    [`PiReadResponseToIr`](../ir.h), and [`PiPacketInToIr`](../ir.h):
    *   Take an `IrP4Info`, a `PI` message or [`IrEntity`](../ir.proto) (or an
        RPC or packet message), and `TranslationOptions`.
    *   Return a canonical `PI` or formatted `IR` message.
    *   Reject unknown IDs, missing mandatory matches or priorities, non-zero
        `@padding` bits, and `@unsupported` elements unless
        [`TranslationOptions::allow_unsupported`](../translation_options.h) is
        set.
*   `PdTableEntryToPiEntity` / `PiEntityToPdTableEntry`, plus
    [`PdTableEntryToIrEntity`](../pd.h), [`PdWriteRequestToIr`](../pd.h), and
    [`IrReadResponseToPd`](../pd.h):
    *   Take an `IrP4Info`, a `pdgen`-generated `proto2::Message`, and
        `TranslationOptions`.
    *   Translate through `IR`, using reflection over the populated table or
        multicast oneof branch.
    *   Fail if no entry branch is set, if field names don't match `IrP4Info`,
        or if wire validation fails.
*   `GrpcStatusToIrWriteRpcStatus` / `GrpcStatusToPd`: Take a batch write
    `grpc::Status` and `number_of_updates_in_write_request`.
    *   Unpack per-update `p4.v1.Error` payloads, or return `N` `OK` statuses
        when the top-level status is `OK`.
    *   Reject malformed `google.rpc.Status` payloads and detail counts that
        don't match `N`.

## Cross-File Invariants

*   **`PD` field-name coupling with `pdgen`**: Reflection in `pd.cc` looks up
    exact snake_case field and submessage names generated by `pdgenlib.cc` (such
    as `<table_alias>_entry`, `match`, `action`, `wcmp_actions`, `group_action`,
    `multicast_group_table_entry`, `counter_data`, `meter_counter_data`).
    Changing any generated field name in `pdgenlib.cc` without a lockstep update
    in `pd.cc` breaks `IR <-> PD` conversion at runtime rather than compile
    time.
*   **Canonical byte strings on `PI -> IR -> PI` round trips**: `PI -> IR`
    parses each byte string into a formatted `IR` value with
    [`ArbitraryByteStringToIrValue`](../ir_utils.h) in
    [`ir_utils.h`](../ir_utils.h), or pads it to `ceil(bitwidth / 8)` bytes with
    [`ArbitraryToNormalizedByteString`](../ir_utils.h). For bitstring formats
    (`HEX_STRING`, `MAC`, `IPV4`, `IPV6`), `IR -> PI` encodes each value at that
    fixed width with [`IrValueToNormalizedByteString`](../ir_utils.h), then
    [`ArbitraryToCanonicalByteString`](../ir_utils.h) strips leading zero bytes
    to the shortest non-empty big-endian byte string (unless
    `ZeroPadPiTableEntry` is explicitly called for BMv2). `Format::STRING`
    values pass through unchanged, without padding or zero stripping. Callers
    cannot assume byte-identical `PI` round trips when input `PI` bytes are
    non-canonical.
*   **Explicit `TranslationOptions` forwarding inside PDPI**: Internal
    `cc_library` targets compile with
    `PDPI_DISABLE_TRANSLATION_OPTIONS_DEFAULT`. This removes the default `{}`
    argument on `TranslationOptions` parameters, so every internal call must
    forward these options:
    *   `.key_only`: Required for `DELETE` updates that omit actions and non-key
        fields.
    *   `.allow_unsupported`: Required to translate `@unsupported` tables, match
        fields, actions, or table action references.
    *   `.allow_arbitrary_format`: Skips `@format` validation (`IPV4`, `IPV6`,
        `MAC`, `STRING`, hex), so `IR` values in any format pass on formatted
        fields.
*   **Batch write `grpc::Status` decoding trusts the caller's count**:
    `GrpcStatusToIrWriteRpcStatus` and `GrpcStatusToPd` never inspect the
    `WriteRequest`.
    *   On `grpc::StatusCode::OK` with an empty message and details, they return
        `number_of_updates_in_write_request` `OK` statuses. A wrong count
        silently gives the wrong number of statuses.
    *   On a non-`OK` code with empty `error_details`, they populate
        `rpc_wide_error`.
    *   On `UNKNOWN` with `error_details`, they return `InvalidArgumentError`
        unless `google.rpc.Status` has code `UNKNOWN` and `details` unpacks to
        exactly `N` `p4.v1.Error` entries with at least one non-`OK` entry.
    *   They also reject details on `OK` or on codes other than `UNKNOWN`.
*   **Packet-IO `@padding` omission and zero-fill**: Packet-IO metadata fields
    annotated with `@padding` set `is_padding` on
    [`IrPacketIoMetadataDefinition`](../ir.proto), are omitted from `IR` and
    `PD` messages, fail `PI -> IR` translation if non-zero, and are synthesized
    as all-zero byte strings on `IR -> PI`.
*   **Pre-resolved `IrP4Info` on packet I/O hot paths**: `CreateIrP4Info`
    validates the full `P4Info` schema and reference graph up front. Callers in
    packet I/O loops must build `IrP4Info` once per stream or instantiation and
    reuse it, not rebuild it per packet.

## Known Limitations

*   **Deprecated `PartialPdTableEntry*` and `IrTableEntries` can't carry
    multicast entries**: [`PartialPdTableEntryToPiTableEntry`](../pd.h),
    [`PartialPdTableEntriesToPiTableEntries`](../pd.h),
    [`PartialPdTableEntryToIrTableEntry`](../pd.h), and
    [`PartialPdTableEntriesToIrTableEntries`](../pd.h) (`ABSL_DEPRECATED`) fail
    on `multicast_group_table_entry` inputs, and [`IrTableEntries`](../ir.proto)
    (`[deprecated = true]`) only holds `IrTableEntry` messages. Use
    `PdTableEntryToPiEntity`, [`PdTableEntriesToPiEntities`](../pd.h),
    [`PdTableEntryToIrEntity`](../pd.h),
    [`PdTableEntriesToIrEntities`](../pd.h), and [`IrEntities`](../ir.proto)
    instead.
*   **Hardcoded ARS table fallback for `weights_disallowed`**:
    [`ir.cc`](../ir.cc) checks `action_profile.weights_disallowed()` to forbid
    member weights on WCMP action sets, keeping a hardcoded fallback for
    `ars_group_table`, `ars_path_profile_table`, and `ars_quality_map_table`
    until `p4c` populates `weights_disallowed` everywhere. A new or renamed ARS
    action-profile table without `action_profile.weights_disallowed` allows
    weighted members unless it is added to that list or `p4c` emits the field.
*   **`IrEntityBuilder` skips validation and packet replication entries**:
    *   It builds table entries without checking the `P4Info` or the P4Runtime
        spec.
    *   It does not build multicast or clone-session entries.
    *   Switching between [`IrEntityBuilder::Action`](../ir_entity_builder.h)
        and [`IrEntityBuilder::ActionSetMember`](../ir_entity_builder.h)
        replaces any earlier single action or WCMP action set.
*   **`TransformValuesOfType` only rewrites `Format::STRING` match values and
    action parameters**: It writes every result as `IrValue::str`.
    *   It skips `action_set.group_action`, `ternary.mask`, and counter, meter,
        and register fields, because `IR` omits `P4NamedType` metadata on
        counters, meters, and registers.
    *   [`VisitValuesOfType`](../ir_tools.h) also copies all of `entries` and
        mutates the copy, which adds allocation overhead on large entry vectors.

## End-to-End Path

1.  **Schema lowering (`P4Info -> IrP4Info`)**: `CreateIrP4Info` parses
    `p4.config.v1.P4Info` type annotations (`@format`,
    `@p4runtime_translation`), table/action definitions, `@groupaction` and
    `weights_disallowed` properties, packet-IO `@padding` flags, and
    `@refers_to` / `@referenced_by` edges + topological table ranks into
    `IrP4Info`.
2.  **`PD -> IR` reflection**: `PdTableEntryToIrEntity` (or
    [`PdWriteRequestToIr`](../pd.h)) inspects the concrete generated PD message
    via `proto2::Message::GetReflection()`, maps the populated table or
    multicast oneof branch, match fields, actions, and `group_action` into an
    [`IrEntity`](../ir.proto), and rejects `@unsupported` branches unless
    [`TranslationOptions::allow_unsupported`](../translation_options.h) is set.
3.  **`IR -> PI` wire encoding**: `IrEntityToPi` (or
    [`IrWriteRequestToPi`](../ir.h)) validates mandatory matches, priority
    presence (required on ternary and optional tables, and forbidden on exact
    and LPM tables; `CreateIrP4Info` already rejects `RANGE` match fields),
    action-profile member weights, and key-only constraints against `IrP4Info`,
    encoding formatted [`IrValue`](../ir.proto) fields into canonical `p4.v1`
    byte strings.
4.  **Switch response & batch status decoding (`PI -> IR -> PD`)**:
    [`PiReadResponseToIr`](../ir.h), [`PiPacketInToIr`](../ir.h), and
    `GrpcStatusToIrWriteRpcStatus` validate wire responses and unpack per-update
    `p4.v1.Error` details from `grpc::Status`, after which
    [`IrReadResponseToPd`](../pd.h) and `GrpcStatusToPd` populate the caller's
    generated PD response or `WriteRpcStatus` message.
